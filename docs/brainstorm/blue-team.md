> 日期:2026-10-01 · 立场:防守 + 建设方 · 对象:dream-layer(P0+P1 已建,160 测试全绿,真实一夜已跑通)
> 方法:先预判红队攻击面,再逐条给出防守论证与加固方案。加固方案一律满足:不破坏红线(配对禁语义相似度 / 梦话不回注 / 晨报无建议 / 人工 confirm 才算有效回流 / 不以命中率为目的调随机性),改动粒度限于配置、参数、单条规则,不动架构。

## 1. 防守论证

### 防守一(T1):随机配对的理论依据不是比喻,是三条独立的学术谱系

**防守点**:强制随机配对(结构受控、语义不受控)是本项目的核心赌注,也是红队的第一靶子。

**为什么这个设计是对的**:

1. **Bisociation(Koestler, 1964)**:创造力的经典定义就是"两条互不相干的参照框架被迫交叉"。注意这个定义的反面:相似度检索是**同一框架内**的移动,按定义不产生 bisociation。这不是修辞——"启发的定义是你没想找的东西撞上了你已有的东西"在认识论上排斥"按目标函数排序的候选集"。相似度预筛不是中立的优化,它会把配对空间投影回查询者的目标函数,系统随之退化为检索器。
2. **REM 睡眠的重激活研究**:REM 中海马体做的是片段化、半随机的记忆重激活,皮层负责把随机激活编织成叙事(Deperrois 2024 PAD 模型 / NeuroDream 综述;§2.2 的映射:pool+配对=海马体,引擎=皮层)。关键含义:**皮层(引擎)不需要改造,梦的内容由激活源喂了什么决定**。红队若攻击"LLM 高温只是幻觉",回击是:我们从未要求引擎产出事实,诚实阀门("这两条没碰出东西"是合法产出)写死在 prompt 骨架里(dreamer.py `SKELETON_LINES`),幻觉风险由两道闸和人工 confirm 三段拦截,而"随机激活源"正是认知科学里 REM 区别于 NREM 的机制。
3. **扩散激活模型(Collins & Loftus, 1975)的对照实验**:SCM 的图随机游走 = 按边强扩散激活(激活沿已建立的语义边流动);我们 = 随机源注入的扩散激活。前者能找到的,边强已经在那里——图结构本身就是相似度的固化;后者是唯一能触达"还没有边的两个节点"的方案。§13.1 里这条已写清楚,它是 §2.3 分歧的理论表述,不是事后贴金。

辅助证据:Oblique Strategies(Eno & Schmidt, 1975)用随机抽卡打破创作僵局,艺术家社区实践五十年并自发贡献了多个版本——"随机刺激作为创造力工具"有半个世纪的产品化先例,personas 池就是它的 agent 版。Spens 2024(Nature Human Behaviour,被引 172+)把"生成式回放"建成海马体巩固的正式计算模型,说明"生成 = 梦的机制"在认知神经科学里是可建模对象,不是文学修辞。

**承认的弱点**:理论谱系只能证明"随机配对是合法的实验设计",不能证明"这个实例会产出洞见"。SCM 的反例就在桌上(见防守五)。我们赌的是生成式联想 + 弃料起点 + 任务态外评估三个变量同时换掉了,属于新实验而非重复实验——但这个论证只有跑完才能闭环。

**加固方案(不破坏红线)**:

- (a) **把"配对禁相似度"从注释升级为可测试断言**:在 tests/ 加一条静态审计用例,扫描 pool.py 禁止出现 `similar|cosine|embedding|distance` 等符号(G1 红线已经有源码审计验收 IT-08,把"配对模块零语义"也固化成用例,防未来贡献者顺手"优化")。改动:一个测试文件,零运行时影响。
- (b) **history_sample 6→12 的评估触发器落地**(FR-A9 已在评估位):在 `dreamlayer metrics` 输出里加一行"跨时对占比 = 跨时间桶配对数/总配对数",两周数据到达时一眼可读,直接支撑上调决议。改动:metrics.py 读 journal meta 聚合,纯读取。
- (c) README 理论段落已有,开源版(P2)把 §13.1 的三条谱系做成"参考文献"小节——叙事加固,零代码。

### 防守二(T2):95% 废话率不是遮羞布,是指标设计的前提

**防守点**:红队会说"95% 是废话"不可证伪——任何失败都能被解释成"还没等到那 5%"。

**为什么这个设计是对的**:

1. **Serendipity 的学术定义**(RecSys 领域标准):serendipity = 意外性 AND 有用性,缺一不可。本项目的指标设计恰好是这两轴的叉乘:Lane A surprise 分(机器、每晚、免费)× 人工 confirm(有用性、稀疏、权威)。梦产率指标 = serendipity@human,这是学术对齐,不是自我安慰。DAT(Divergent Association Task)被批评"只测新颖不测恰当"——我们的双轴恰好补上被批评的那一半。
2. **可证伪性其实存在,而且写进了 PRD**:FR-I1 五个指标全部有 8 周基线/目标(误杀回收 ≥1/月、趋势预警 ≥1、跨时确认 ≥1、梦产率 ≥1 有效回流/2 周)。8 周到期校准。如果 8 周全零,按 PRD 自己的逻辑这就是失败信号——项目没有给自己留"永远等一下"的后门。存在感指标(两周后是否期待晨报)更是主观但决定性的死刑条款。
3. **成本结构让"等待 5%"是理性策略**:每晚 ≤ 数千 token(20 次小调用)+ 规则筛选近零;占用的本来就是凌晨闲置算力(Sleep-time Compute 的成本论证,§13.2)。期望价值 = p(洞见) × 洞见价值 − 每晚成本。成本趋零时,极低的 p 就足以让期望为正。这不是宗教,是彩票的算术——前提是把成本钉死在近零,这正是 NFR1 和 FakeLLM 存在的理由。
4. **废话有副产品**:即使梦话全是废话,保底产物(drift.svg 被拒池漂移图、band.svg 邻近带曲线,FR-I2)独立于梦话价值运行。"95% 废话"的夜晚,素材池的统计形状仍然在产出。这是把"失败夜的残值"显性化的设计。

**承认的弱点**:95% 目前是假设不是测量。真实一夜的样本太小(20 对,3 条回流,1 条真实跨时关联),不能外推。"8 周全零就认输"的纪律必须真的执行,否则红队的"不可证伪"指控会事后成立。

**加固方案**:

- (a) **废话率如实进 metrics 输出**:打印"近 14 夜:入梦 X 夜 / 回流 Y 条 / 确认 Z 条 / 诚实阀门直说'没碰出东西' W 次"。最后一项(dreamer 的 `raw` 命中"没碰出东西"的计数)是免费的健康信号——占比过高说明素材质量或配对约束有问题,占比过低反而可疑(引擎在硬凑)。改动:metrics.py 聚合 dreams jsonl,纯读取。
- (b) **套话词密度周检脚本**(§7 失败模式表已有检测信号定义:"交织/融合/赋能/未来已来"词表):落成 `dreamlayer metrics --cliche` 一段,读两周 journal 算命中密度趋势。这是对"陈词滥调退化"的现成对策,目前只在文档里,没变成可运行的一个函数。改动:一个函数 + 一个词表配置项(放 rhythm.yaml,不进代码,符合 §5 宪法)。
- (c) 不做的加固:任何"提高命中率"的配对调整(FR-B6 明文禁止)。这条要写进报告是因为红队会建议"用 confirm 数据反哺配对权重"——那是自激回路的入口,拒绝。

### 防守三(T3):晨报"观察+问题、无建议无行动项"是防退化的结构,不是功能残缺

**防守点**:红队会说用户没有行动项就不会持续打开晨报,产品活不过两周。

**为什么这个设计是对的**:

1. **建议 = 目标函数回注**。晨报一旦给建议,读者的行为就被梦的内容引导;被引导的行为产生新素材;新素材入池再入梦——梦开始塑造自己的输入,第二视角死亡。这是原则 6(防退化)的具体化:"让梦更有用"的需求就是任务态的需求。FR-D3 把 actionability 评分做成"不存在"(不是"低分",是字段级缺席),是正确的过度防御。
2. **祈使检测是写死在代码里的机械闸**(waker.py `IMPERATIVE_MARKS`,命中"建议/应该/下一步/值得做/可以考虑/需要你/记得去"即降 noise),不是 prompt 里的软请求。这意味着即使引擎试图给建议,产物也到不了晨报。"原则不能只活在提示词里"这条工程纪律本身就是防守资产。
3. **产品先例证明小剂量无建议形态可持续**:Readwise Daily Review 每天推送旧高亮,无建议、无行动项、被动、小剂量,是成熟商业产品。晨报 ≤3 条/天上限不是我们发明的克制,是照抄被验证过的 UX(§13.2)。用户天天打开的理由不是"有用",是仪式感和低认知负荷——存在感指标(§1.3)测的正是这个,不是效率。
4. **"提问不给答案"有独立价值**:open_question 通过 grounding 闸强制落到具体指称(专名/数字/低频词),它把"你应该注意 X"转换成"X 和 54 天前的 Y 是什么关系"——前者是命令(可被抵抗),后者是钩子(好奇心自驱)。真实第一夜的那条 WebFetch × 54 天前笔记,价值恰恰在于"点破"而非"指导"。

**承认的弱点**:祈使词表是纯中文的。引擎(尤其英文 prompt 习惯的模型)可能产出英文建议("you should...", "next step...")绕过闸。这是真实漏洞,不是理论风险。

**加固方案**:

- (a) **IMPERATIVE_MARKS 补英文集**:`("you should", "next step", "worth doing", "consider ", "recommend", "action item", "don't forget")`。改动:waker.py 一个常量元组,测试加两例。成本十分钟,堵住的是闸 1 的最大侧门。
- (b) **晨报加"为什么是这条"一行**(lane A/B + surprise 分 + 锚点明细):让读者能自己判断该信几分,把机器暂定 verdict 的"暂定"属性可视化。这也服务 E3(降低 confirm 决策成本)。改动:sink.py 渲染模板一行,数据已在 Reflux 对象里。
- (c) 不做的加固:任何"可选行动项开关"。开关一旦存在,等于把防退化责任推给用户配置,原则 6 要求这个决定留在设计层。

### 防守四(T4):与 Obsidian / ResearchRabbit / Readwise 的实质差异是"生成 vs 索引"

**防守点**:红队会说跨时点破 Obsidian unlinked mentions 已经做了,随机刺激 Readwise 已经做了,拼接怪没有增量。

**为什么这个设计是对的**:逐个拆。

| 产品 | 它做的 | 本质差异 |
|---|---|---|
| Obsidian unlinked mentions | 笔记库内,被动列出"提到了但没链接" | ① 范围封闭:只在笔记库内,看不到对话废料/被拒条目/研究文档之间;② 触发被动:你得打开那篇笔记;③ **零生成**:它只是索引现有共现,不产生任何新文本。本项目的跨时关联是高温生成出来的观察+问题,且素材域是全管线(暗物质优先)。真实第一夜的 WebFetch 关联,素材一半在 zcode 会话废料里——Obsidian 永远看不到它 |
| ResearchRabbit / 文献推荐 | 引文图 + 相似度扩展 | 方向相反:从已知出发沿边走(扩散激活的边强版),本项目是随机源注入。它找到的是"你正在找的领域里的未知",不是"你没想找的领域" |
| Readwise Daily Review | 间隔重复重现旧高亮 | 无配对、无碰撞、无生成——是单条重播,不是双条碰撞。它是 NREM 的消费者产品形态(巩固),借的是它的 UX 频控,不是机制 |
| SCM | 图随机游走 + 重要性种子 | 见防守五 |

差异的本质一句话:**它们全是索引与重播(信息已在库里,只是摆到你面前);本项目是生成(观察文本在碰撞前不存在于任何地方)**。索引方案的上限是"点破已存在的连接",生成方案的上限是"制造一个此前不存在的陈述"。95% 的生成是废话,但剩下 5% 是索引方案在原理上够不着的东西。

**承认的弱点**:这个差异论证对"生成的那 5% 是否比索引漏掉的更多"没有先验答案。可能存在反例:Obsidian 的被动点破在用户基数上累计的洞见总量超过我们的主动生成。我们不声称取代,只声称覆盖了一个它们原理上不在的格子(全素材域 × 主动生成 × 无目标)。

**加固方案**:

- (a) README 已有区隔段落;把上面这张表(四行)直接放进开源 README 的"它不是什么"小节(P2 任务,叙事加固)。
- (b) **Lane B 配额使用率进 metrics**(见防守六):跨时点破是本项目与索引方案重叠最多的部分,它的信号质量必须用数据盯着,否则"实质差异"会退化成口号。

### 防守五(E1):SCM 的"REM 无可测收益"是评估失配的证据,不是 REM 的死刑

**防守点**:这是最锋利的一击——唯一做过 REM 的先行工作(arXiv 2604.20943)在消融中自认事实回忆基准上无可测收益。红队会问:你凭什么不一样?

**为什么这个设计是对的**(三点分歧,§2.3 已有,这里给出论证强度排序):

1. **评估轴错了,不是 REM 错了**(最强论证):SCM 用**事实回忆基准**测 REM。事实回忆是 NREM(巩固)的目标函数——巩固做得好,回忆就准。REM 的假设收益是远距离联想与创造性重组,这个轴在事实回忆基准上**结构性不可见**——就像用体重秤测身高。SCM 的消融结果因此有两种解读:(i) REM 无用;(ii) REM 的用处不在该基准的射程内。SCM 作者自己写的是后者("当前评估未能验证其功能收益")。本项目的存在性证明因此**不依赖** SCM 失败的原因是 (ii)——我们把评估轴换成了存在感/serendipity@human,这是一个 SCM 没测过的轴。
2. **机制不同:结构重组 vs 生成式联想**。SCM 的 REM 是记忆图上的随机游走(步长 5),产出是重排后的记忆结构;本项目是 LLM 高温下的文本生成。前者不产生新陈述,后者产生。§8 的开源叙事一句话已钉死这个分歧。
3. **起点不同:珍宝堆 vs 弃料堆**。SCM 的种子是重要性加权(任务相关 0.35 最高)——从任务态的精品出发;本项目从被拒/犹豫/废弃出发(hesitated 3.0 / rejected 2.0),暗物质优先。SCM 的 REM 即使有效,也触及不到 P1 暗物质痛点,因为被拒数据根本不在它的记忆图里。

**承认的弱点**:以上三点论证的是"SCM 的失败不传递给我们",不是"我们会成功"。也可能 SCM 失败的真实原因是 (i)——REM 对机器就是无用,而我们的"晨报给人看"路线只是换了个消费方,洞见率同样趋零。8 周基线是裁决者,在此之前这条防守只是"无罪推定",不是"无罪判决"。诚实地说:这是全部防守里置信度最低的一条,也是项目之所以是"赌注"的原因。

**加固方案**:

- (a) **趋势预警对账机制落地**(FR-I1 第二行已定义:trend 断言登记后 14 天对账):这是把"REM 收益"从主观印象变成可对账记录的关键机制。当前状态:指标定义存在,对账动作靠人记。加固:`dreamlayer confirm <id> trend` 时在 reflux_log 条目里加 `due: confirmed_at + 14d` 字段,`dreamlayer metrics` 打印"到期未对账的 trend 预警列表"。改动:reflux.py 加 5 行,metrics.py 加 10 行,纯追加字段不破坏契约。
- (b) 不做的加固:不引入事实回忆类基准自测——那正是 SCM 掉进去的坑,我们的轴不在这。

### 防守六(E2):规则筛选是"可审计的粗糙",优于"不可审计的精致"——但有两个真洞要补

**防守点**:红队攻击 surprise 公式(0.4/0.3/0.3 拍的)、bigram 分词(粗糙)、Lane B(数字"2"也直通)。这条攻击部分成立。

**为什么这个设计是对的**(先防守可防守的部分):

1. **纯规则是有意的认识论选择**。FR-C5 把 embedding 替换放在"待校准集"评估位——校准集不另造,从 journal 人工标注攒(每周 ≥20 对)。顺序是刻意的:先跑可解释的粗糙规则攒标注数据,再决定要不要上不可解释的精致模型。反过来做(先上 embedding)会导致筛选层从一开始就不可审计,违背了 NFR7 审计性这条非功能需求。**在单人项目里,可调试性 > 理论精度**——0.4/0.3/0.3 错了能看懂错在哪,embedding 错了只能换模型祈祷。
2. **Lane B 的存在本身就是对规则局限的承认**:纯 surprise 会误杀"跨时共享实体"(共享专名拉低 lexical_novelty),所以开了稀有锚点直通车道。这是"知道自己的规则会犯哪类错,并为这类错开旁路"的设计,比"相信单一分数"成熟。
3. **两道闸兜住下游**:即使 Lane A/B 放进误报,祈使检测 + grounding(问题必须含 evidence 的专名/数字/低频词)会把"看起来意外但落不到具体细节"的片段拦在晨报外。真实一夜 20 对 → 3 条晨报,过滤率 85%,闸在干活。

**承认的弱点**(不硬撑,红队打这两点是打中了):

- (w1) **数字锚点无长度/上下文过滤**:`numbers()` 抽取 `\d+(?:\.\d+)?`,两条素材都出现"2"或"10"即触发直通。短数字在自然文本中碰撞概率极高,是 Lane B 最大的误报源。当前缓解只有配额(5 条/夜)和两道闸,属于"放行后拦截",不是"源头收窄"。
- (w2) **RARE_DF_MAX=0.05 在小池子里近乎无过滤力**:池 52 条时,df < 5% 意味着 token 出现在 ≤2 条素材里;而共享 token 至少在 2 条素材里出现——所以几乎任何共享 bigram 都"稀有"。中文 bigram("系统""设计"这类未被停用词覆盖的通用词)会大量刷进 Lane B。真正干活的是 proper(拉丁专名)和 numbers。真实一夜 3 条晨报全是 cross_time(Lane B),与这个分析一致:Lane A 实际上被 Lane B 的宽松压制了。
- (w3) surprise 权重无校准——这条有 FR-C5 的诚实路线图兜底,算"已承认的债务",不算被打中。

**加固方案**(全部是一条规则级):

- (a) **数字锚点加最小位数**:锚点数字要求 ≥4 位或含小数点(年份、版本号 2.49、id 号才配当锚点;"2"不配)。改动:waker.py `numbers()` 一个过滤条件 + 两个测试用例。**这是全报告优先级最高的单条改动**——它直接削掉 Lane B 最大误报源,成本约十分钟。
- (b) **rare token 加绝对计数下限**:除 df < 0.05 外,要求该 token 在池内出现次数 ≥2 且 ≤ max(2, 5%·N)——数学上把"稀有"钉在"恰好这两条共享",消掉小池子的退化;或更简单:rare 锚点要求 bigram 字符长度 ≥2 且命中"专名/数字"任一时才算强锚点,纯 bigram 锚点降权排在 lane B 尾部。改动:waker.py lane_b_anchor 排序键,配置可加 `rare_df_abs_max` 放 rhythm.yaml。
- (c) **Lane B 配额使用率进 metrics**:每晚 lane_b 命中数/配额 5,连续打满即说明锚点过松(或池子真有大量跨时实体——两种情况都要知道是哪种)。改动:meta 加一个字段(NFR7 允许 meta 扩展,journal 模板 meta 行已是自由字段串),metrics 聚合打印。

### 防守七(E3):人工 confirm 不是瓶颈,是这个系统唯一不能被自动化的部件

**防守点**:红队会说 confirm 依赖用户纪律,两周后确认率归零,指标与 quiet_cycle 全死。

**为什么这个设计是对的**:

1. **confirm 是"有效回流"定义的一部分,不是事后补的日志动作**。没有人工确认,"有效"这个词就没有判官——LLM 自评有用性是著名的不可靠(自指:让幻觉发生器评判幻觉)。§13.3 的两个反例("Agents Got a Sleep Phase"工程反思、2606.03979 合成数据直接入训练回路)演示的都是同一个失败:梦的产出在没有人工闸门时变成被记住的事实或被训练的信号。FR-J1(不回注)+ FR-D4(人工 confirm)是这对反例的直接回应。**闸门不是 UX 妥协,是安全部件**。
2. **confirm 成本被刻意压到极低**:`review` 交互向导逐条 1/2/3/s/q,每天 ≤3 条候选,单次过审约 30 秒;`review --batch` 允许 agent 在对话中收集判决后批量登记。这个成本低于刷一次 RSS。如果用户连 30 秒都不愿意花,那存在感指标(§1.3)已经判了死刑——**confirm 率本身就是存在感的度量**,这不是 bug 是设计。
3. **confirm 归零不等于系统崩溃,等于系统安静**:quiet_cycle(7 天无确认 → 隔日梦)正是为"用户冷淡期"设计的自弃机制——它把"没人看还硬跑"的资源浪费和打扰都减半,同时保底产物(metrics.write_report 在 wake_phase 里无条件执行,scheduler.py 第 265 行)继续跑。系统在冷淡期退化成"每周两张统计图 + 隔日晨报",这是体面的降级,不是死亡。
4. **verdict 暂定 vs 人定案的双层**已经在晨报上写明(README 已知限制第一条),降低了 confirm 的心理门槛——用户不是在做"审核工作",是在"认领巧合"。

**承认的弱点**:真实弱点不在 confirm 机制本身,而在**趋势预警的 14 天对账**(防守五 a)目前没有提醒机制,纯靠人记。confirm 一次容易,14 天后回来对账很难。这是 E3 攻击唯一真正咬得动的地方。

**加固方案**:

- (a) 防守五 (a) 的 `due` 字段 + metrics 到期列表,就是这条的加固,不重复。
- (b) **晨报底部已带 confirm 命令提示**(FR-D1);加固为把当天 3 条的 dream_id 直接拼成可复制的命令行(`dreamlayer review --batch "id1:cross_time"`),把 30 秒压到 10 秒。改动:sink.py 渲染一行。
- (c) 不做的加固:任何形式的"自动 confirm"(如 LLM 二审代替人)。这是红线中的红线——一旦机器能定案,有效回流指标即刻失效,quiet_cycle 失去意义,整个反馈环变成自激。

### 防守八(E4):单人可持续性的答案不是毅力,是"成本归零 + 失败有残值 + 热情有仪表盘"

**防守点**:红队会说单人业余项目三个月必烂尾,这是统计事实不是侮辱。

**为什么这个设计是对的**:这条攻击的前提(单人项目高死亡率)成立,但它把死因归错了。单人项目死于三件事:维护成本随时间增长、失败无残值导致挫败、缺乏正反馈。本项目对三件事各有结构性对策:

1. **维护成本归零的设计**:CI 全 FakeLLM 零网络零花费(NFR1);运行时依赖仅 pyyaml + openai(懒加载,不装也能跑 fake 和测试);纯文件存储无数据库;160 测试就是回归基线,不需要额外基建。引擎可插拔(FR-B5)对冲端点涨价/变动(R3)——换 base_url 即换引擎,GLM/DeepSeek/ollama 通用。采集端配置驱动 + 坏行跳过(R2),源格式变了改 yaml 不改代码。**项目闲置一个月,回来时它应该还能跑**——这是单人项目可持续的真正定义。
2. **失败有残值**:梦产率长期为 0(R4,可能性"高",PRD 自己登记的)时,保底产物 drift.svg / band.svg 仍在产出(给垃圾场装监控,对标内容审核灰区队列的工业实践);journal 永久留档可读;两周的晨报本身是可回看的日记体。**项目最坏结局是"一个安静的统计仪表板",不是"一堆废代码"**。
3. **热情有仪表盘**:存在感指标把"我是否还期待晨报"变成两周一次的显性自检,而不是让热情悄悄流失到弃坑才发现。quiet_cycle 把冷淡期制度化——它甚至会自己降低存在感来避免被厌烦,然后在你某次 confirm 后自动恢复。这个反馈环是单人项目里罕见的"与用户关系"设计。

**承认的弱点**:R1(时间碎片化)在 PRD 风险登记里可能性标"高",这是诚实的——以上结构只能降低死亡概率,不能消除。真正的死亡场景是:作者换工作/换技术栈,采集源全部失效,没有人回来改 yaml。没有任何设计能防这个,承认它。

**加固方案**:

- (a) **GitHub Actions 跑 pytest**(若开源):FakeLLM 零网络,CI 零成本,一次配置永久有效。这是把"160 测试"从本地资产升级为公共信任资产。改动:一个 yaml 文件。
- (b) **README 加"回来指南"小节**:三个月没碰这个项目,回来做的第一件事(`run --once --fake` 看一夜假梦 → 看 metrics → 决定续不续)。把"回归成本"显性写到一页以内,直接对冲 R1。改动:文档一段。
- (c) 不做的加固:不引入数据库、不引入 embedding 重依赖(NFR4)。每加一个重依赖,三个月后的回归成本就翻一倍——NFR4 表面是性能条款,实际是存活条款。

### 防守九(T0,主动展示):隐私与自激防线是读代码后最难攻击的阵地

**防守点**:红队若审计代码,会优先找隐私和反馈回路的洞。这里主动展示,因为它是全项目防御密度最高的地方。

**为什么这个设计是对的**:

- **排除先于读取**(FR-H1):`.env`/密钥/凭据/node_modules 的 glob 在**打开文件之前**生效(collectors 层),不是读完再删——这是"默认 deny"的正确实现顺序,读都没读就不存在泄漏路径。
- **内容脱敏双保险**(FR-H2):正则命中替换 + 打码占比 >0.3 整条丢弃(防"整篇都是密钥"的边界情形);正则预编译(FR-H5)说明性能终审也过了。
- **密钥与 URL 不落盘**:API key 只走 `DREAM_LLM_API_KEY` 环境变量,webhook URL 只走环境变量名引用(FR-D2),engine.yaml 里没有 secret 字段可填。
- **journal 本地 only**(FR-E2):落盘路径含 OneDrive/Dropbox/百度网盘/坚果云/iCloud 标记即拒绝写——梦话(可能含你的犹豫和被拒念头)永不进云同步。
- **自激双闸**:FR-J1 梦话永不回注主池 + echo 池默认关(FR-J2)且即使开也"不与梦话配对、只作种子"——种子能进梦但梦仍自由生长,这是 MIT Dormio 孵梦实验在人身上验证过的机制(§13.1),不是拍脑袋。

**承认的弱点**:redact_patterns 只覆盖四种密钥形态(sk-/AKIA/ghp_/password 赋值)。私有服务的自定义 token 格式(如内部系统的 `Bearer xxx` 变体)不在其列。缓解:配置驱动——加一条正则是 privacy.yaml 的事,不是发版的事。

**加固方案**:

- (a) privacy.yaml 的 redact_patterns 补两条通用高熵形态:`(?i)bearer\s+[A-Za-z0-9._-]{20,}` 和 `[A-Za-z0-9+/]{40,}={0,2}`(base64 长串,后者误报率需观察——先加 bearer 一条即可,base64 待两周真实数据决定)。改动:配置两行。
- (b) 不做的加固:不把脱敏做成可关开关。默认 deny 的价值就在于"关它需要改文件留痕"。

## 3. 蓝队总裁决

### 裁决:**【现状即可跑】**

理由:P0+P1 已建成且 160 测试全绿;真实素材一夜已跑通并产出一条真实跨时关联(命中率样本虽小,方向正确);五条红线全部在代码层(而非文档层)生效;失败有残值、成本归零、自弃机制在位。项目的真验收(存在感指标 + 8 周基线)本来就是"跑起来才能测"的指标——停下来加固到完美再跑,恰恰会错过本赛季(素材池 90 天滚动窗口内的数据时效)。

W1–W3 是真实误报源,但它们的伤害被配额和两道闸限制在"晨报质量打折",不构成"跑起来"的阻塞;它们是"跑的过程中顺手修"的级别。
