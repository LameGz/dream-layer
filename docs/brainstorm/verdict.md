## 二、全场最重的一击,单独展开:Lane B 后门

红队攻击 7 的原文逻辑链,值得逐字面对:

1. 红线:配对禁止语义相似度(G1);
2. 但 waker.py 的 Lane B:共享低频 token / 数字 / 专名 → 直通、锁 cross_time、配额保护;
3. 共享专名/数字 = 实体级相似度;
4. 系统唯一真实战果(WebFetch × 54 天前笔记)恰恰走的就是 Lane B;
5. **结论:项目最大的成功案例,证伪了项目的核心原则。**

蓝队的回应(防守二/六)是"配对层禁相似度仍是纪律,Lane B 在筛选层,而且它是为规则误杀开的旁路"。这个回应解释了**位置**,没回答**实质**:如果实体共现是对的筛选标准,为什么它不能是对的配对标准?

**我的裁决:红队说对了一半,但它开的药方(锚点配对占 30%)会破坏红线;蓝队的防守缺了一半,它没说出 Lane B 的合法性来源。**

正确的解读是:**配对层和筛选层对"相似度"的容忍度本来就不同,这不是虚伪,是分工。** 配对层禁相似度,是因为它决定"哪些组合有机会被看见"——一旦相似度进来,配对空间就坍缩回目标函数,发散性死亡。筛选层用锚点,是因为它只决定"已生成的梦话里哪些值得给人看"——它不缩小可能性空间,只在产出里打捞确定性信号。一个是入口纪律,一个是出口打捞,方向相反,不冲突。

**但红队的实证指控必须接住**:战果全部来自 Lane B,说明 Lane A(纯意外度)至今颗粒无收。这不证伪红线,但要求一个实验:**每晚 journal meta 里区分 lane A / lane B 的回流来源,8 周后看确认率各来自哪条道。** 如果 Lane A 确认率为 0 而 Lane B 有货,那"随机碰撞"的真实价值就要重新定价——到那时再讨论 Lane B 前移不迟。现在前移,是用一天的样本量改写宪法。

## 四、红队独胜区(蓝队没接住的,必须处理)

这四条不是"顺手修",是产品级决定,需要你拍板:

### D1. 隐私默认:云端 vs 本地(红队攻击 5)

现状:engine.yaml 默认 `open.bigmodel.cn`(云端智谱),而 mdfile 会把整篇笔记发过去。"梦话不出本机"的叙事与默认配置矛盾。

三个选项:
- **A. 默认本地(ollama),云端 opt-in** —— 红队药方;隐私叙事闭环,但本地小模型质量会让废话率从 95% 变成 99%,晨报可读性下降
- **B. 保持云端默认,README 加警告框"素材将离开本机"** —— 诚实但叙事降级
- **C. 加 `privacy.mode: local_only` 硬开关,开启时云端引擎拒绝启动** —— 折中:默认仍是云端(开发顺畅),但隐私模式一行配置可开

我的建议:**C,且 README 必须写明默认是云端**。开源前(P2)再评 A——等 ollama 预设建好、DAT 测过本地小模型的发散度之后。

### D2. 推送形态:每日晨报 vs 事件驱动(红队攻击 4)

红队药方:只有 Lane B 锚点命中才推,其余攒周报——信噪比从 5% 拉到 ~100%。
蓝队立场:晨报是每日仪式,存在感指标的载体;quiet_cycle 是体面降级。

我的建议:**现阶段不动,但加一个观测**:metrics 里记"晨报打开率"(用 review 命令的调用时间近似)。红队的"安乐死剧本"和蓝队的"仪式先例"都有道理,区别只在打开率数据——8 周后如果打开率 <30%,切事件驱动;>60%,维持。让数据拍板,不现在拍。

### D3. 注意力成本(红队攻击 9)

open_question 每天向读者收认知税。修法便宜:晨报每条下面加一行"不想可以当废话,这就是 95% 的那部分"——明示豁免权,清掉心理债务。sink.py 模板一行,本周顺手做。

### D4. Kill switch(红队攻击 8)

写进 README 的预先承诺:**90 天后若有效回流 < 3 条,项目归档,保底图表拆成独立小工具。** 这是对抗沉没成本的唯一武器,也是给"不可证伪"指控的最终回答——框架不是两头都赢,它有死刑日期。

## 五、对照实验设计(C5,两队共识的最大缺口)

红队的药方简化后可行版本(不破坏红线,只是新增一个旁路实验):

```
实验期:14 天
分组:同一素材池,每晚 A/B 交替
  A 夜:现有随机配对(对照组)
  B 夜:实验配对 = 锚点对(实体共现优先,占 50%)+ 随机对(50%)
     —— 注意:不是"相似度配对",是"锚点配对";红队的 embedding 相似度配对
        违反 NFR4 零向量依赖,且 embedding 版本留待 FR-C5 校准集
评估:review 时盲评(不看 dream_id 的奇偶),confirm 率按组统计
判定:B 组确认率显著高于 A 组 → 锚点机制承重,考虑 Lane B 前移(改架构,过 PRD 评审)
     两组相当 → 随机机制与锚点等效,红线保留,"禁止相似度"体面存活
     A 组更高 → 意外性本身在承重,蓝队大胜
```

实现成本:pool.py 加一个 `build_pairs(mode="anchor_mix")` 旁路(不动现有配对),scheduler 读 `experiment.ab: true` 配置项交替,metrics 按组聚合。约 50 行 + 测试。

## 六、最终裁决

**【现状即可跑,但跑之前先系三条安全带】**

红队的"大改后勉强一试"和蓝队的"现状即可跑"都对了一半:
- 蓝队对的部分:实验只有跑了才有数据;真验收(存在感/8 周基线)本来就要跑起来才能测;工程结构已经能跑。
- 红队对的部分:有三条安全带不系,跑了也白跑——隐私叙事与现实矛盾(D1)会在开源时爆炸;无对照(C5)会让 8 周数据无法解读;无 kill switch(D4)会让失败变成僵尸。

所以最终处方:

**本周(开跑前):**
1. C1/C2/C3 三个闸的修补(各约 10 分钟)
2. D1 选项 C:privacy.mode 硬开关 + README 写明默认云端
3. D3:晨报豁免行
4. D4:README 写 90 天 kill switch
5. C4:due 字段 + metrics 到期列表
6. C5:对照实验旁路(50 行)

**跑起来后(8 周数据期):**
7. metrics 增强:废话率/诚实阀门命中率/Lane B 配额使用率/晨报打开率/lane 来源分组
8. 晨报底部拼可复制的 review --batch 命令
9. redact_patterns 补 bearer 形态
10. 配对零语义静态审计测试

**8 周后(数据裁决日):**
- 打开率 <30% → 切事件驱动推送(D2 红队药方生效)
- Lane A 确认率 0% 且 Lane B 有货 → 启动 Lane B 前移的 PRD 评审
- 有效回流 <3 条 → 执行 kill switch,项目归档,保底图表独立发布

明确不做(两队一致或红线明文):confirm 数据反哺配对权重;LLM 二审代替人工;可选行动项开关;embedding/数据库重依赖;以提高命中率为目的调随机性。
